# 챕터 3 설계 방침

## 신규 메커닉 3종
| 구간       | 메커닉             | 도입 방식                          |
|------------|--------------------|------------------------------------|
| 3-1 ~ 3-6  | StepOn + Tg        | 소개 → 시험 → 복합 3단계            |
| 3-7 ~ 3-10 | TrapToggle         | 소개 → 시험 → 복합                  |
| 3-11 ~ 3-15| ColorToggle        | 소개 → 시험 → 전체 복합 마무리      |

## 행동 제한 도입
- 3-1 ~ 3-5: limitALT=0, limitF4=0 (무제한)
- 3-6: limitALT=8 첫 등장 (최적해 ~4회, 여유 +4)
- 3-10: limitALT=6 (여유 +2)
- 3-14: limitF4=7, limitALT=5 (타이트하게)
- 3-15: limitF4=6, limitALT=4 (챕터 피크)

## 리마인더 정책
3-1~3-3에 챕터 2 메커닉 1개씩 유지
- 3-1: Q> (회전 타일) 리마인더
- 3-2: Br (Breakable) 리마인더
- 3-3: T1/t1 (텔레포트) 리마인더

## 복잡도 낙차 기준
- 연속 스테이지 타일 수 변화: 최대 40% 이내
- 9→10타일(+11%) 증가 권장, 10→7타일(-30%) 이내로 제한

## 3-1: StepOn 첫 소개
**의도:** "StepOn 밟으면 막힌 길(Tg)이 열린다" 단일 체험
**타일 수:** 8 | **limit:** 없음 | **레이아웃:** L자
**리마인더:** Q> (시계 90° 회전 타일)

```
[S ][Q>][  ][  ]
    [So][H ][  ]
    [Tg][. ][G ]
    [★ ][  ][  ]
```

경로: S → Q>(맵 90° 회전 체험) → So(Tg 열림) → Tg → . → G
      ★ 는 Tg 아래 (Tg를 통과해야 접근 가능, 선택 수집)

설계 포인트
- Tg 초기=막힘. So를 밟기 전에는 G 방향이 봉쇄됨
- Q>로 맵이 회전해도 So→Tg 경로는 유지 (회전 후 재확인 학습)
- 실패 시: So 없이 Tg에 접근 시도 → 통과 불가 → "밟아야 열린다" 자연 인지

---

## 3-2: StepOn 시험 — "다시 밟으면 다시 닫힌다"
**의도:** StepOn 토글 특성 학습 (밟을 때마다 Tg 상태가 반전)
**타일 수:** 9 | **limit:** 없음 | **레이아웃:** ㄷ자
**리마인더:** Br (Breakable)

```
[S ][Br][So][H ]
[  ][  ][Tg][  ]
[  ][. ][★ ][G ]
```

경로: S → Br(균열 체험) → So(Tg 열림) → Tg → ★ → G
함정: So를 두 번 밟으면 Tg 다시 닫힘 → ★ 또는 G 방향 봉쇄

설계 포인트
- So는 경로 위에 있어서 지나치면 두 번 밟힘 위험
- Tg 아래에 ★이 있어서 수집 욕심이 재진입을 유도 → 자연스럽게 "두 번 밟기 위험" 체험
- Br 리마인더: 균열 타일 1개 통과로 ch2 기억 환기

## 3-3: StepOn 복합 — 텔레포트 + StepOn 순서
**의도:** 텔레포트와 StepOn 순서 결합 (ch2 텔레포트 리마인더)
**타일 수:** 9 | **limit:** 없음 | **레이아웃:** T자
**리마인더:** T1/t1 (텔레포트)

```
[  ][So][Tg][  ]
[S ][T1][. ][G ]
[  ][t1][★ ][H ]
```

경로 설명
- T1(왼쪽 위)에서 t1(왼쪽 아래)으로 텔레포트
- t1에서 나오면 So 위쪽이 아닌 아래쪽 진입 경로로 재배치됨
- So 밟으려면 텔레포트 후 위쪽으로 올라가야 함 → 텔레포트를 활용해야 So 접근 가능

설계 포인트
- 텔레포트 사용 여부가 So 접근 경로를 결정
- 단순 직진으로는 So를 못 밟아서 Tg가 열리지 않음
- 총 경로: S → T1 → t1(텔레포트 도착) → 위 이동 → So → Tg → G

## 3-4: 다중 StepOn — So 2개, Tg 2개
**의도:** 각각 독립된 So-Tg 쌍을 순서대로 활성화
**타일 수:** 10 | **limit:** 없음 | **레이아웃:** 2열 병렬

```
[So1][H ][So2][  ]
[Tg1][. ][Tg2][  ]
[S ][. ][. ][G ]
[  ][★ ][H ][  ]
```

경로: S → 위 → So1(Tg1 열림) → 오른쪽 → So2(Tg2 열림) → Tg1/Tg2 통과 → G
핵심 선택: So1 먼저 밟느냐 So2 먼저 밟느냐에 따라 접근 가능한 경로가 달라짐

설계 포인트
- So1 후 So2: Tg1→Tg2 순서로 개방 → 직선 경로
- So2 후 So1: Tg2→Tg1 순서 → 역방향 진입 필요
- ★은 Tg1 아래, 수집 시 Tg1 재활성 주의 필요

## 3-5: StepOn + RotationToggle 복합 — 타이밍 충돌
**의도:** RT 발동과 So 발동이 같은 Tg를 공유 → 발동 순서가 핵심
**타일 수:** 11 | **limit:** 없음 | **레이아웃:** ㅁ자 우회

```
[S ][RT][. ][So]
[  ][Tg][. ][H ]
[  ][. ][★ ][G ]
```

설정: RT(2회 회전 → Tg 발동), So(밟으면 Tg 발동)
Tg 초기=막힘

경로 옵션 A: So 먼저 밟아 Tg 열기 → RT 아직 미발동 → Tg 통과 성공
경로 옵션 B: RT 먼저 2회 발동(Tg 열림) → So 밟으면 Tg 다시 닫힘 → 통과 실패

설계 포인트
- 사망 함정: RT 발동 후 So 밟으면 Tg 다시 잠김 (카운트 소진 사망 패턴)
- 정답은 So를 먼저, RT는 발동 전에 통과
- ★은 Tg 통과 후 도달 가능한 위치

## 3-6: limitALT 첫 등장 + StepOn 마무리
**의도:** 행동 제한 속에서 So 활성화 타이밍 관리
**타일 수:** 11 | **limitALT: 8** (최적 ~4, 여유 +4) | **레이아웃:** 2층 ㄴ자

```
[  ][So ][. ][H ]
[S ][Tg ][. ][★ ]
[  ][. ][So ][  ]
[  ][. ][Tg ][G ]
```

경로: S → 위 → So(상층 Tg 열림) → 오른쪽 → ★ → 아래 2층 → So(하층 Tg 열림) → Tg → G
ALT 8회 제한: 최적 경로는 4회 회전이면 충분 → 여유 있게 클리어 가능
학습: "제한이 있지만 여유롭게 풀면 된다"는 첫 인상이 중요

설계 포인트
- 불필요한 회전을 4회 이상 낭비하면 실패 가능성 있음 (학습 유도)
- 처음 제한 등장이므로 H 타일로 "남은 횟수 확인" 힌트 배치

---

## 3-7: TrapToggle 첫 소개
**의도:** "TrapToggle이 OFF 상태이면 위에 있으면 폭발. 먼저 켜야 안전"
**타일 수:** 8 | **limitALT: 8** | **레이아웃:** 직선

```
[S ][So][H ][  ]
    [  ][Tg][Tr][G ]
```

설정: Tr 초기=OFF(위험). So 밟으면 Tg(=Tr에 연결된 제어 타일)가 발동 → Tr ON으로 전환
경로: S → So(Tg 발동 → Tr ON) → 오른쪽 → Tg → Tr(이제 안전) → G

설계 포인트
- So를 밟지 않고 Tr에 접근하면 즉시 폭발 → "선 활성화, 후 통과" 인지
- H 타일: "이 주황 타일을 먼저 활성화하세요" 힌트 역할
- TrapToggle은 시각적으로 ON/OFF 상태가 명확히 구분되어야 함

---

## 3-8: TrapToggle 시험 — "Tr이 여러 개, 순서 중요"
**의도:** TrapToggle 2개를 각각 다른 So로 활성화 → 순서 학습
**타일 수:** 10 | **limitALT: 8** | **레이아웃:** T자 분기

```
[So1][  ][So2][H ]
[Tr1][. ][Tr2][  ]
[S ][. ][. ][G ]
```

설정: Tr1은 So1으로, Tr2는 So2로 각각 제어
경로: S → 위 분기 → So1(Tr1 ON) → 돌아와서 → So2(Tr2 ON) → Tr1 → . → Tr2 → G

설계 포인트
- So1만 밟고 Tr2에 접근하면 폭발
- So를 두 번 밟으면 Tr이 다시 OFF → 주의
- 최적 경로: So1 → So2 → Tr1 → Tr2 → G (각 So를 1회씩만)

---

## 3-9: TrapToggle + StepOn 복합
**의도:** So가 Tg와 Tr을 동시에 제어 → 한 번의 활성화로 두 타일에 영향
**타일 수:** 10 | **limitALT: 8** | **레이아웃:** L자

```
[S ][. ][So][  ]
    [  ][Tg][H ]
    [  ][Tr][★ ]
    [  ][. ][G ]
```

설정: So 밟으면 → Tg(막힌 벽) 열림 & Tr ON (동시 발동)
경로: S → . → So → 아래 → Tg(통과 가능) → Tr(안전) → ★ → G

설계 포인트
- So 한 번으로 두 효과가 동시 발동됨을 보여주는 첫 사례
- So를 두 번 밟으면 Tg 다시 닫힘 + Tr 다시 OFF → 양쪽 모두 위험

---

## 3-10: TrapToggle + RotationToggle 복합
**의도:** RT 발동이 Tr을 ON 시킴 (이동 카운트가 함정을 무력화하는 역발상)
**타일 수:** 11 | **limitALT: 6** (여유 +2) | **레이아웃:** ㄷ자

```
[S ][RT][. ][Tr][H ]
    [  ][  ][. ][G ]
    [★ ][. ][. ][  ]
```

설정: RT(3회 회전 → Tg 발동 → Tr ON), Tr 초기=OFF
경로: S → RT 위치 → 회전 3회 이내 실행 → RT 발동 → Tr ON → Tr → G
경로 대안: ★ 먹으러 하단 우회 (extra 이동 발생 → RT 발동 타이밍 어긋날 수 있음)

설계 포인트
- 회전 6회 제한 속에서 RT를 정확히 3회에 발동시켜야 함
- ★ 수집 경로가 여분 회전을 소비 → 도전적 선택
- RT가 Tr을 제어하는 구조는 "Toggle과 TrapToggle의 상호작용" 첫 사례

## 3-11: ColorToggle 첫 소개 — Red 단색
**의도:** "ColorToggle(Red)을 밟으면 같은 색(Red) Tg가 반응한다"
**타일 수:** 8 | **limitALT: 6** | **레이아웃:** L자

```
[S ][CoR][  ]
    [TgR][H ]
    [G ][★ ]
```

설정: CoR = ColorToggle(Red), TgR = ToggleTargeted(Red 색상, 초기=막힘)
경로: S → CoR(Red 이벤트 → TgR 열림) → 아래 → TgR → G
★ G 옆 (선택 수집)

설계 포인트
- ColorToggle을 밟으면 같은 색의 ToggleTargeted만 반응함을 직관적으로 전달
- 첫 소개이므로 색상 1종류만 사용
- H 힌트: "같은 색 표시를 찾아보세요"

## 3-12: ColorToggle 시험 — Red + Blue 2색
**의도:** 두 가지 색상 ColorToggle이 독립적으로 각각의 Tg를 제어
**타일 수:** 10 | **limitALT: 6** | **레이아웃:** 십자형

```
[  ][CoB][  ]
[CoR][S ][TgB]
[  ][TgR][H ]
[  ][G ][★ ]
```

설정: CoR → TgR(Red), CoB → TgB(Blue)
경로 예시: S → CoR(TgR 열림) → 아래 → TgR → G
또는: S → CoB(TgB 열림) → 오른쪽 → TgB → 우회 → G (더 긴 경로)

설계 포인트
- Red와 Blue를 따로 밟아야 각자의 Tg가 열림
- 최단 경로: CoR → TgR → G (CoB/TgB 무시)
- ★ 수집 경로: CoB 활성화 → TgB 통과 후 ★

## 3-13: ColorToggle + TrapToggle 복합
**의도:** ColorToggle로 TrapToggle의 ON/OFF를 제어 (색상 기반 함정 해제)
**타일 수:** 11 | **limitALT: 6** | **레이아웃:** ㄷ자

```
[CoR][  ][CoB][H ]
[TrR][. ][TrB][  ]
[S ][. ][. ][G ]
[  ][★ ][  ][  ]
```

설정: CoR → TrR(Red TrapToggle) ON/OFF, CoB → TrB(Blue TrapToggle) ON/OFF
Tr 초기=OFF(위험)

경로: S → CoR(TrR ON) → CoB(TrB ON) → TrR → . → TrB → G
함정: CoR을 두 번 밟으면 TrR 다시 OFF → 위험

설계 포인트
- 색상 기반으로 함정 타일을 안전하게 만들어야 하는 퍼즐
- CoR→CoB 순서 또는 CoB→CoR 순서, 각각 다른 경로 경유 필요
- 우회 경로(★ 방향) 이용 시 추가 CoR 밟기 없이 통과 가능

## 3-14: 챕터 3 복합 스테이지 — StepOn + TrapToggle + limit
**의도:** So, Tr, Tg 모두 활용 + limitF4 첫 등장
**타일 수:** 12 | **limitF4: 7, limitALT: 5** | **레이아웃:** ㅁ자 우회

```
[  ][So ][H ][  ]
[S ][Tg ][. ][Tr]
[  ][. ][So ][  ]
[  ][★ ][Tg ][G ]
```

설정: 상층 So → 상층 Tg 제어, 하층 So → 하층 Tg 제어
Tr: 별도 ColorToggle 없이 이미 ON 상태 (초기=ON=안전)이지만 RT(2회) 발동 시 OFF로 전환

경로: S → 위 → So1(Tg1 열림) → 오른쪽 → Tr(주의: RT 발동 전 통과) → 아래 → So2 → Tg2 → G
한정된 이동/회전 횟수 안에서 So → Tr → So → G 순서 유지가 핵심

설계 포인트
- limitF4=7: 최적 경로 약 5회 이동, 2회 여유
- Tr 함정: RT가 2회 발동 전에 통과하면 안전
- ★ 수집 경로는 추가 이동 소비 → 선택적 도전

## 3-15: 챕터 3 피크 — ColorToggle + TrapToggle + limit 복합
**의도:** 챕터 3에서 배운 3가지 신규 메커닉 전부 활용 + 타이트한 제한
**타일 수:** 13 | **limitF4: 6, limitALT: 4** | **레이아웃:** 복합

```
[CoR][  ][CoB][H ]
[TrR][So][TrB][  ]
[S ][Tg][. ][★ ]
[  ][. ][. ][G ]
```

설정
- CoR → TrR ON/OFF (Red TrapToggle)
- CoB → TrB ON/OFF (Blue TrapToggle)
- So → Tg 제어 (막힌 중앙 통로)
- Tr 초기=OFF(위험)

해법 경로

## 4-1: TAB 첫 소개 — 맵 전환 기초
**의도:** "TAB을 누르면 다른 맵으로 이동한다. 두 맵을 오가며 경로를 찾는다"
**타일 수:** Map1: 6 / Map2: 5 | **limitTAB: 4** | **레이아웃:** 직선
**리마인더:** So + Tg (ch3)

```
=== MAP 1 ===
[S ][So][Tg][  ][G ]

=== MAP 2 ===
[  ][. ][. ][H ][  ]
```

설명
- Map1: Tg(초기=막힘)가 G 앞을 가로막음. So 밟으면 Tg 열림
- Map2: Map1의 Tg 위치에 해당하는 Map2 경로는 뚫려 있음
- TAB으로 Map2로 이동 → 장애물 우회 → 다시 TAB으로 Map1 귀환 → G
- 또는: Map1에서 So 밟기 → Tg 열림 → 직접 G 접근 (TAB 불필요 루트)

설계 포인트
- TAB 없이도 클리어 가능 (TAB은 보조 수단으로 먼저 소개)
- limitTAB=4: 최적 경로에서 TAB 사용 횟수 ~2, 여유 2회
- 가장 중요한 교훈: "TAB은 같은 위치에서 다른 맵으로 이동한다"
